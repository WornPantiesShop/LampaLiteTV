# Сетевое ожидание TCL C645 — 28.10.2026

Версия 1.5.16-c645 (22). Исправление локализовано в транспорте HDrezka и его
однопоточной ограниченной очереди; каталожный CSS, анимации и системная сеть не менялись.

## Причина

В прежнем JS abort() удалял только объект ожидания и таймер. Уже начатая Java-задача
продолжала соединение/чтение и занимала единственного worker, а устаревшие задачи
оставались в очереди. JS-тайм-аут 25 с также не отменял нативную работу.

Добавлены резервирование задания до асинхронного take(), непрозрачная команда
rezka-cancel, FutureTask.cancel и удаление из очереди, проверка отмены между
редиректами и чтениями. HttpURLConnection.disconnect запускается в отдельном ленивом
служебном потоке, поскольку HTTP-реализация устройства может блокироваться при
закрытии. UI не ожидает закрытия сокета. Лимиты очереди, одного сетевого worker,
размера ответа, HTTPS-доменов и путей POST сохранены.

## Доступность с реального подключения

Одно наблюдение Resource Timing уже загруженного каталога:

- api.themoviedb.org: 3 запроса, среднее 205 мс.
- image.tmdb.org: 27 запросов, среднее 573 мс, максимум 1320 мс.
- lampa.mx: 51 запрос, среднее 205 мс.

Это не контролируемый сетевой benchmark и не гарантия для каждого фильма/CDN.
Оснований принудительно менять DNS или добавлять прокси эти данные не дали.

## Проверки

- Java-тест использует блокирующее чтение, которому для завершения нужен disconnect.
  При модельном тайм-ауте 2000 мс отмена освободила очередь для следующей задачи за
  1 мс в наблюдаемом проходе. Проверены отмена до submit(), 16 ожидающих заданий,
  восстановление ёмкости очереди, отмена активного соединения и подавление завершения
  отменённых задач. Это лабораторная проверка механизма, не замер ускорения сервера.
- JS-тесты проверили abort, поздний ответ, тайм-аут, cookies, фильтр разрешённых URL,
  одноразовые ID и отсутствие чувствительных данных в командах навигации.
- На ТВ выполнен GET /robots.txt существующего разрешённого домена kvk.zone. При
  abort фиксировались active=1 и inFlight=1 (Native take уже выполнен). Затем второй
  GET вернул HTTP 200 за 814 мс. После: active=0, inFlight=0, requests=2,
  cancelled=1, timedOut=0. Тело ответа и cookies в журналы не выводились.
- install-tv.ps1: прежняя подпись, install -r, ceDataInode=114783 сохранён.
- После обновления остались 4 загруженных ряда, русский язык интерфейса, режим
  плеера ask и наличие сохранённой авторизации. Навигация D-pad проверена.
- Тесты выбора плеера и продолжения просмотра Vimu прошли повторно.

FPS в этой задаче не сравнивался. Исправление уменьшает накопление отменённой
сетевой работы; оно не снимает ограничения сайтов и не гарантирует доступность
всех источников. Реальный зависший сервер на ТВ не имитировался системными
настройками сети: этот сценарий покрыт контролируемым Java-тестом.

Java-тест: скомпилировать CancelableRequestQueue.java и tools/CancelableRequestQueueTest.java
в отдельный каталог, затем запустить com.example.lampalitetv.CancelableRequestQueueTest.
JS: node tools/test-rezka-transport.mjs.
